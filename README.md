# WRG 2026 Japan — เว็บไซต์ตารางทีม

เว็บไซต์ตารางแข่งขันและประกาศอัปเดตสำหรับทีม **Soccer 4x4** และ **Ball Fighting**
งาน WRG Robot Games 2026 · Chiba Port Arena, Japan · 16–20 พ.ย. 2569

เว็บนี้มี **2 โหมดการรัน** เลือกได้ตามสถานการณ์:

| โหมด | ใช้เมื่อ | เก็บข้อมูลที่ |
|---|---|---|
| **Vercel + Supabase (Postgres)** (แนะนำสำหรับ production) | โฮสต์จริงให้ทีมเข้าถึงได้ทุกที่ | ฐานข้อมูล Postgres บน Supabase |
| **Local server (legacy)** | ทดสอบเครื่องตัวเอง หรือใช้ในงานที่ Wi-Fi ไม่เสถียร/ไม่มีเน็ต | ไฟล์ `data/db.json` บนเครื่อง |

> เคยลองใช้ MySQL บนเซิร์ฟเวอร์ของตัวเองมาก่อน แต่ติดปัญหา CGNAT (ISP บ้าน
> แชร์ IP สาธารณะเดียวกันกับลูกค้าหลายคน ทำให้เชื่อมต่อเข้ามาจากอินเทอร์เน็ตไม่ได้
> เลยไม่ว่าจะตั้งค่าไฟร์วอลล์ยังไง) จึงย้ายมาใช้ Supabase ซึ่งเป็น Postgres
> แบบโฮสต์ให้พร้อมใช้ ไม่ติดปัญหาเครือข่ายบ้าน และมี free tier ที่เพียงพอสำหรับเว็บนี้

## โหมดที่ 1: Vercel + Supabase (แนะนำ)

### ทำไมต้องเปลี่ยนจากไฟล์ JSON

โหมด local server เดิมเก็บทุกอย่าง (ประกาศ, ตารางแข่ง, สมาชิก, สถานะล็อกอิน) ไว้ใน
ไฟล์เดียวบนดิสก์ของเครื่องที่รันอยู่ **Vercel ไม่มีดิสก์แบบถาวรให้เขียนไฟล์** —
รันเป็น serverless function ที่แยกกันทุกครั้ง ถ้าเอาโค้ดแบบเดิมขึ้น Vercel ตรง ๆ
การแก้ไขทุกอย่างจะดูเหมือนบันทึกสำเร็จแล้ว **หายไปเงียบ ๆ** ในคำขอถัดไป
และการล็อกอินจะหลุดแบบสุ่ม เพราะ session เก็บไว้ในหน่วยความจำที่ไม่ได้แชร์กัน

เว็บนี้จึงมีแบ็กเอนด์ชุดที่สอง (`/api/*.js` + `/lib/*.js`) ที่เก็บข้อมูลทั้งหมดใน
ตาราง Postgres แทน และใช้ signed cookie สำหรับ session แทนหน่วยความจำ — ใช้งานได้ถูกต้อง
บน serverless

### ตั้งค่าครั้งแรก

**1) สร้างโปรเจกต์ Supabase** (ฟรี) — สมัครที่ [supabase.com](https://supabase.com)
สร้างโปรเจกต์ใหม่ แล้วไปที่ **Project → Connect** เพื่อดู connection string

ใช้ **Transaction pooler** (พอร์ต 6543) เสมอ ทั้งตอน setup ในเครื่องและตอน deploy —
**อย่าใช้ Direct connection (พอร์ต 5432)**: hostname ของ direct connection บน
Supabase ชี้ไปที่ IPv6 อย่างเดียว ถ้าเน็ตบ้าน/ออฟฟิศไม่มี IPv6 ใช้งานได้ (พบได้บ่อย)
จะต่อไม่ติดเลย ขึ้น error `ENETUNREACH` — ตัว pooler รองรับทั้ง IPv4/IPv6 และรองรับ
serverless function ที่เปิด connection สั้น ๆ จำนวนมากได้ดีกว่าด้วย จึงใช้ตัวเดียว
ได้ทั้งสองที่ ไม่ต้องสลับ

**2) ติดตั้งและตั้งค่าการเชื่อมต่อ:**

```bash
npm install
cp .env.example .env   # แล้วกรอก DATABASE_URL ด้วย transaction pooler string
```

**3) สร้างตารางในฐานข้อมูล** — ไม่ต้องมี `psql` CLI ติดตั้งในเครื่อง สคริปต์นี้ใช้
แพ็กเกจ `pg` ที่ลงไว้แล้วจากขั้นตอนที่ 2 เชื่อมต่อโดยตรง:

```bash
node scripts/apply-schema.js
```

รันซ้ำได้เรื่อย ๆ ไม่มีปัญหา (ใช้ `CREATE TABLE IF NOT EXISTS`)

**4) นำเข้าข้อมูลปัจจุบัน** (ถ้ามี `data/db.json` อยู่แล้วจากโหมด local):

```bash
node scripts/migrate-from-json.js data/db.json
```

ถ้ายังไม่มีข้อมูลเลย ใช้ `data/seed.json` แทนได้ (ข้อมูลตั้งต้นจากเอกสารทางการ):

```bash
node scripts/migrate-from-json.js data/seed.json
```

**5) สร้างรหัสผ่านผู้ดูแล:**

```bash
node scripts/hash-password.js "รหัสผ่านที่ต้องการ"
```

จะได้ `ADMIN_SALT` และ `ADMIN_HASH` มาใส่เป็น environment variable (รหัสผ่านจริง
ไม่ถูกเก็บไว้ที่ไหนเลย มีแต่ hash)

**6) ตั้งค่า Supabase Storage** (สำหรับแท็บ "ไฟล์เอกสาร"):

ใน Supabase dashboard ไปที่ **Storage** → สร้าง bucket ใหม่ 2 อัน ทั้งคู่ตั้งเป็น
**private** (ไม่ใช่ public) — แอปสร้าง signed URL ให้เองตอนดาวน์โหลด/อัปโหลด:

- `trip-files` — เอกสารรวมของทีมที่ทุกคนเห็นได้ (แท็บ "ไฟล์เอกสาร")
- `member-files` — เอกสารส่วนตัวของแต่ละคน เช่น พาสปอร์ต, QR Visit Japan
  (แท็บ "ตรวจสอบข้อมูล") แยก bucket ต่างหากโดยเจตนา เพื่อไม่ให้การเรียกดูไฟล์ทีม
  แบบไม่ต้องล็อกอินหลงไปเจอไฟล์ส่วนตัวของใครได้

จากนั้นไปที่ **Project → Settings → API** คัดลอก **Project URL** และ
**service_role key** (ไม่ใช่ anon key) ใส่เป็น `SUPABASE_URL` และ
`SUPABASE_SERVICE_ROLE_KEY` ใน `.env` (ดูรายละเอียดใน `.env.example`) — ตัวแปร
ชุดเดียวกันนี้ใช้ได้กับทั้งสอง bucket

**7) Deploy ขึ้น Vercel:**

- Push โค้ดนี้ขึ้น GitHub repo ของคุณ
- สร้าง Vercel project ใหม่ แล้วเชื่อมกับ repo นั้น (Vercel จะ auto-detect
  `/api/*.js` เป็น serverless functions และเสิร์ฟ `/public` เป็นไฟล์ static
  โดยอัตโนมัติ ไม่ต้องตั้งค่า build command)
- ใน Vercel → Project → Settings → Environment Variables ใส่ตัวแปรทั้งหมดจาก
  `.env.example` — ใช้ `DATABASE_URL` เดียวกับที่ใช้ตอน setup (transaction pooler)
- Deploy

### Environment variables

ดูรายการทั้งหมดพร้อมคำอธิบายใน [`.env.example`](.env.example) — คัดลอกเป็น `.env`
สำหรับทดสอบในเครื่อง (ไฟล์นี้ไม่ถูก commit ขึ้น git)

> **ห้าม** ใส่รหัสผ่านหรือ connection string ลงในแชทหรือโค้ดที่ commit ขึ้น
> GitHub — ใส่เฉพาะใน `.env` (local) หรือ Vercel dashboard (production) เท่านั้น

### รันทดสอบในเครื่องก่อน deploy

```bash
npm install -g vercel   # ครั้งแรกครั้งเดียว
vercel dev
```

จะรันทั้ง `/api/*` และไฟล์ static เหมือนบน Vercel จริง แต่อยู่ในเครื่อง

## โหมดที่ 2: Local server (legacy — ไม่มี Vercel/Supabase)

เหมาะสำหรับทดสอบเร็ว ๆ หรือใช้ที่งานถ้า Wi-Fi ไม่เสถียร (รันบนโน้ตบุ๊กของคุณ
แชร์ผ่าน Wi-Fi เดียวกัน ไม่ต้องพึ่งอินเทอร์เน็ต) — ไม่ต้อง `npm install`
ใช้ Node.js ล้วน ไม่มี dependency

```bash
node server.js
```

เปิด http://localhost:8080

ครั้งแรกที่รัน ระบบจะ **สุ่มรหัสผ่านผู้ดูแลให้อัตโนมัติ** และพิมพ์ออกมาใน terminal
พร้อมบันทึกไว้ที่ `data/FIRST-RUN-PASSWORD.txt` — **เข้าสู่ระบบครั้งแรกแล้วลบไฟล์นี้ทิ้ง**

ตั้งรหัสผ่านเองได้ทุกเมื่อ:

```bash
node server.js --set-password "รหัสผ่านใหม่ของคุณ"
```

เปลี่ยนพอร์ต (เช่นถ้าพอร์ต 8080 ถูกใช้อยู่):

```bash
PORT=3000 node server.js
```

> โหมดนี้กับโหมด Vercel+Supabase เก็บข้อมูลคนละที่กัน ไม่ sync กันอัตโนมัติ —
> ใช้ `scripts/migrate-from-json.js` เพื่อย้ายข้อมูลจาก local ไป Supabase ตอนไหนก็ได้

## การแก้ไขข้อมูล — เฉพาะคุณเท่านั้น

1. กดปุ่ม **"ผู้ดูแล"** (รูปกุญแจ) มุมขวาบน → ใส่รหัสผ่าน
2. เมื่อเข้าสู่ระบบแล้วจะมีแถบสีแดง "โหมดผู้ดูแล" ขึ้นมา และปุ่มแก้ไขจะปรากฏทุกหน้า

แก้ไขได้:

| ส่วน | วิธีแก้ |
|---|---|
| **ประกาศ / อัปเดต** | ปุ่ม `+ ประกาศใหม่` — มีฟอร์มให้กรอก เลือกระดับความสำคัญและทีมที่เกี่ยวข้อง |
| **สถานะการแข่ง** | ดรอปดาวน์ข้างแต่ละแมตช์ (ตามกำหนด / กำลังแข่ง / จบแล้ว / ยกเลิก / เปลี่ยนเวลา) |
| **ข้อมูลทีม + รหัสทีม** | ปุ่ม `แก้ไขข้อมูลทีม` บนการ์ดทีม — ชื่อทีม, **รหัสทีม**, วันแข่ง, สนาม, คำอธิบาย |
| **สมาชิกทีม + รหัสประจำตัว** | ในหน้าทีม — ปุ่ม `เพิ่มสมาชิก` และปุ่มแก้ไข/ลบ ที่ท้ายแต่ละแถว |
| **รายการแข่ง** | ในหน้าทีม — ปุ่ม `เพิ่มรายการแข่ง` และปุ่มแก้ไข/ลบ ที่ท้ายแต่ละรายการ |
| **เช็กลิสต์** | ในหน้าทีม — ปุ่ม `เพิ่มรายการ` และปุ่มแก้ไข/ลบ ที่ท้ายแต่ละข้อ |

### รหัสทีม และ รหัสประจำตัวนักแข่ง

- **รหัสทีม** (เช่น `SR-014`) ใส่ได้ที่ปุ่ม `แก้ไขข้อมูลทีม` บนการ์ดทีม
  เมื่อใส่แล้วจะขึ้นเป็นป้ายบนการ์ดทีมทั้งหน้าภาพรวมและหน้าทีม
- **รหัสประจำตัว** (เช่น `TH-0451`) ใส่ได้ตอนเพิ่ม/แก้ไขสมาชิกแต่ละคน
  จะแสดงต่อท้ายชื่อในรายชื่อสมาชิก

ทั้งสองช่องเป็น **ข้อความอิสระ** ไม่บังคับรูปแบบ ใส่ตามที่ผู้จัดกำหนดได้เลย
และเว้นว่างไว้ก่อนได้ถ้ายังไม่รู้ (ป้ายจะไม่ขึ้นจนกว่าจะใส่ค่า)
ตัวรหัสแสดงด้วยฟอนต์ monospace เพื่อให้อ่าน/ขานตัวเลขได้ชัด ไม่สับสนระหว่าง 0 กับ O
| **ตารางแข่ง, กำหนดการ, หมายเหตุ, ข้อมูลทริป** | ปุ่ม `แก้ไข` ข้างหัวข้อนั้น ๆ |

คนอื่นที่เปิดเว็บ **ดูได้อย่างเดียว** — ทุก endpoint ที่เขียนข้อมูลต้องมี session cookie
ของผู้ดูแล ยกเว้น `/api/verify` (op "lookup"/"files-list"/"files-download-url") ซึ่งเปิดให้
ใครก็เรียกได้โดยไม่ต้องล็อกอิน แต่เป็น **read-only** ทั้งหมด — ดูข้อมูลของ "ตัวเอง" ได้
โดยพิสูจน์ตัวด้วยวันเกิดที่ตรงกับข้อมูลในระบบ แก้ไขอะไรไม่ได้เลย (แก้ได้เฉพาะผู้ดูแล)

### ตรวจสอบข้อมูล (ให้สมาชิกทีมค้นหาข้อมูลตัวเอง)

แท็บ "ตรวจสอบข้อมูล" ให้สมาชิกทีม **พิมพ์วันเกิดของตัวเอง** (วว/ดด/ปปปป) — ไม่ต้องเลือกชื่อ
เพราะวันเกิดอย่างเดียวก็หาตัวตนเจอแล้ว (ไม่มีใครในทีมเกิดวันเดียวกัน) ไม่ต้องล็อกอิน เมื่อ
วันเกิดตรง ระบบจะโชว์ (ดูได้อย่างเดียว แก้ไขอะไรเองไม่ได้ — ผิดตรงไหนให้ติดต่อผู้ดูแล):

- ข้อมูลส่วนตัว (โรงเรียน, พาสปอร์ต, วันเกิด, ไซส์เสื้อ, อาหาร, เลขบัตรประชาชน)
- เอกสารส่วนตัวที่ผู้ดูแลอัปโหลดให้ (พาสปอร์ตสแกน, QR จาก Visit Japan Web ฯลฯ) — ดู/ดาวน์โหลดได้
- ตารางแข่งของทีม + รายการแข่งอื่น ๆ ส่วนตัว

ใครอยู่ในรายชื่อมากกว่าหนึ่งทีม (เช่น พี่เลี้ยงที่ดูแลทั้งสองทีม) จะเห็นข้อมูลรวมเป็นคนเดียว
ครอบคลุมทุกทีมที่อยู่

ผู้ดูแลกดปุ่ม "คัดลอกลิงก์ส่งให้ทีม" บนแท็บนี้ (มีเฉพาะตอนล็อกอินอยู่) เพื่อคัดลอกลิงก์
`/verify` ที่เปิดมาตรงแท็บนี้ทันที — ส่งลิงก์เดียวกันนี้ในกลุ่มแชทได้เลย (ลิงก์เก่าแบบ
`?verify=1` ก็ยังใช้ได้อยู่ เผื่อเคยแชร์ไปแล้ว)

**สำหรับผู้ดูแล**: ในหน้าทีม ที่รายชื่อสมาชิกแต่ละคน มีปุ่ม "ข้อมูล" เปิดหน้าเต็มของคนนั้น
(ไม่ใช่ popup) รวมทุกอย่างไว้ที่เดียว — แก้ไขข้อมูล, รูปโปรไฟล์, และเอกสารส่วนตัว
(อัปโหลด/ดาวน์โหลด/ลบ — พาสปอร์ตสแกน, QR Visit Japan ฯลฯ)

## ลิงก์ของแต่ละหน้า

ทุกแท็บมี URL ของตัวเอง แชร์ลิงก์ไปให้คนอื่นเปิดตรงหน้านั้นได้เลย ไม่ต้องกดเลือกแท็บเอง —
เช่น `/timeline` (ไทม์ไลน์), `/schedule` (ตารางแข่ง), `/files` (ไฟล์เอกสาร), `/soccer4x4` และ
`/ballfighting` (หน้าทีม) เป็นต้น จัดการฝั่ง client ล้วน ๆ (ไม่รีโหลดหน้าเว็บ) ปุ่ม
ย้อนกลับ/ไปข้างหน้าของเบราว์เซอร์ก็ใช้งานได้ตามปกติ

ฝั่งเซิร์ฟเวอร์แค่ส่ง `index.html` เดิมให้ทุก URL ที่ไม่ใช่ `/api/*` หรือไฟล์ static จริง ๆ
(ตั้งค่าผ่าน `rewrites` ใน `vercel.json` สำหรับโหมด Vercel+Supabase, หรือ fallback ใน
`server.js` สำหรับโหมด local) แล้วให้ JavaScript ฝั่ง client อ่าน path แล้วเลือกแท็บเอง

## การแจ้งเตือน

- ผู้ชมกดปุ่ม **รูปกระดิ่ง** มุมขวาบนเพื่อเปิดการแจ้งเตือนของเบราว์เซอร์
- เว็บจะตรวจสอบข้อมูลใหม่ทุก **15 วินาที** (และทันทีเมื่อกลับมาที่แท็บ)

### โลโก้ WRG Robot Games

ติดตั้งเรียบร้อยแล้ว:

| ไฟล์ | ใช้ที่ไหน |
|---|---|
| `public/logo.png` | โลโก้เต็ม (1242×655, พื้นหลังโปร่งใส) แสดงที่หัวเว็บมุมซ้ายบน สูง 40px / มือถือ 34px |
| `public/favicon.png` | ไอคอนแท็บเบราว์เซอร์ — ครอปเฉพาะเฟือง + ตัว W ให้เป็นสี่เหลี่ยมจัตุรัส 256×256 |

ต้องแยกเป็น 2 ไฟล์เพราะโลโก้เต็มเป็นแนวนอน (อัตราส่วน 1.9:1) ถ้าเอาไปทำ favicon
โดยตรงจะถูกบีบจนอ่านไม่ออกที่ขนาด 16px จึงครอปเฉพาะส่วนเฟืองมาใช้แทน

**ถ้าจะเปลี่ยนโลโก้ใหม่:** วางไฟล์ทับที่ `public/logo.png` (หรือใช้ `logo.svg` ก็ได้
เว็บจะลองหา `.svg` ก่อน) แล้วสร้าง favicon ใหม่ด้วย:

```bash
magick public/logo.png -crop 480x465+8+25 +repage -background none -gravity center -extent 500x500 -resize 256x256 public/favicon.png
```

ถ้าไฟล์โลโก้หายไป หัวเว็บจะแสดงกล่องสีน้ำเงินคำว่า "WRG" แทนโดยอัตโนมัติ — ไม่มีรูปแตก

### เรื่องธีมและไอคอน

ธีมเป็นแบบ **liquid glass** โทนเขียว WRG — พื้นหลังเป็นแสงสีเขียวเบลอเคลื่อนไหวช้า ๆ
การ์ดทุกใบเป็นกระจกฝ้าโปร่งแสง (`backdrop-filter: blur()`) มีขอบไฮไลต์ด้านบน
มุมโค้งใหญ่ และยกตัวขึ้นเล็กน้อยเมื่อเอาเมาส์ชี้

**เรื่องสีเขียวที่ต้องระวัง** — สีเขียวในโลโก้คือ `#2EB358` แต่ค่า contrast
กับพื้นขาวอยู่ที่ **2.73:1** ซึ่ง *ไม่ผ่าน* มาตรฐาน WCAG AA (ต้องได้ 4.5:1)
จึงแยกการใช้งานเป็น:

| ตัวแปร | ค่า | ใช้กับ |
|---|---|---|
| `--brand-bright` | `#2EB358` | **ตกแต่งเท่านั้น** — แสงพื้นหลัง เส้นไทม์ไลน์ ขอบช่องกรอก ห้ามใช้กับตัวอักษร |
| `--brand` | `#1A7A37` | พื้นปุ่มที่มีตัวอักษรสีขาว (5.41:1) |
| `--brand-dark` | `#13652B` | สถานะ hover / ตัวอักษรเน้น (7.18:1) |
| `--brand-ink` | `#167030` | ลิงก์และตัวอักษรสีเขียวบนกระจก (5.75:1) |

ไล่เฉดสี (gradient) ทุกอันที่มีตัวอักษรสีขาวทับ ถูกตรวจแล้วว่า **ปลายที่สว่างที่สุด
ก็ยังผ่าน 4.5:1** ถ้าจะแก้สีเอง อย่าลืมเช็กปลายด้านสว่างด้วย ไม่ใช่แค่ค่ากลาง

รองรับเบราว์เซอร์ที่ไม่มี `backdrop-filter` (จะเปลี่ยนเป็นพื้นขาวทึบแทน)
และถ้าผู้ใช้ตั้งค่า *ลดการเคลื่อนไหว* ในระบบ พื้นหลังจะหยุดนิ่ง

**เว็บนี้ไม่ใช้อิโมจิเลย** ทุกไอคอนเป็น SVG แบบเส้น เก็บรวมไว้เป็น sprite
ที่ด้านบนของ `public/index.html` (แต่ละอันคือ `<symbol id="i-ชื่อ">`)

ถ้าจะเพิ่มไอคอนใหม่: เพิ่ม `<symbol id="i-xxx" viewBox="0 0 24 24">…</symbol>`
ใน sprite แล้วเรียกใช้ในโค้ดด้วย `icon('xxx')` — **อย่าใส่อิโมจิลงในข้อความ**

**กู้คืนข้อมูลกลับเป็นค่าตั้งต้น:** ลบ `data/db.json` แล้วรีสตาร์ทเซิร์ฟเวอร์

**สำรองข้อมูล:** คัดลอก `data/db.json` เก็บไว้
